## 0. 核对结论（先看这五条）

1. **98.4% 不是 UI 对齐度。** 202.77/206 是「端点 / 界面 / 证据（有测试覆盖）」三维取最低的功能覆盖分。一条路由可以功能满分，却从未做过同状态截图对照。UI 对齐必须单独记账，不能拿 98.4% 宣称「界面已和竞品一致」。
2. **真正的同状态视觉对照目前只有 9 组**：首页、项目列表、剧集工作台、项目资产、资产库、资产确认、时间线编辑、项目内时间线、3D 导演台。93 条可比路由中，功能口径 43 条 full / 21 条 partial / 29 条 none，但 full ≠ 视觉或手感已对齐。
3. **操作手感目前不能宣称对齐。** 竞品 Web 的点击步数没有证据（只有 Agent/CLI 口径：资产 4 步、分镜 3 步、项目 1 步、剧本 1 步），我方核心最短路径约 **21–22 次点击 + 1 次输入**，3 集 × 10 镜典型路径约 **150 次点击**。这些是代码审计值，不是同任务录像对照值。
4. **P0 不是视觉 polish，而是会让用户白干或重复劳动的 4 件事**：批量投递缺 `mode`、`已出片` 三处口径不一致、`匹配资产` 入口不可用、编辑器数据安全（误删 / 未保存 / 区间越界 / 弹窗不可关）。
5. **能自查的自己查，不能自查的标「待证据」。** 既定安全约束不变：不提取/复用浏览器会话凭据、不绕过竞品登录、不执行竞品任何写操作（分享、购买、生成、删除均不触发）。竞品侧仍缺 18 项证据；**D4 已确认本轮拿不到有积分账号录屏**，因此这些动态状态先标 `⏳`，只用 2026-10-25 的 0 积分静态截图做能做的对照；不把「没证据」写成「已对齐」。

## 1. 验收标准：UI 对齐的四层

### 1.1 四层定义

| 层 | 名称 | 判定 | 证据 |
|---|---|---|---|
| **L0** | 路由 / 入口存在 | 路由可达、入口可点、无死链、无「点了没反应」 | 路由表 + 入口截图 + 点击后 URL/网络 |
| **L1** | 同状态视觉一致 | 同视口、同页面、同状态；布局盒 + 计算样式 + 截图对照 | 1424×805 截图 + DOM box/style JSON |
| **L2** | 交互 / 步数一致 | 入口 → 完成的点击数、默认值、闸门、反馈（加载/空/错/成功）、撤销/确认、键盘、窄屏 | 可复跑脚本 + 点击计数 + 网络断言 |
| **L3** | 行为 / 数据一致 | API 字段、状态语义、计费、权限、任务生命周期 | 契约测试 + 状态矩阵 + 端到端用例 |

**只有 L1 + L2 都通过，路由才可以标「UI 对齐」。** 数据型页面（项目、资产、计费、任务）还必须过 L3。
L0 通过但 L1/L2 未做的，只能标「功能存在」，不能标「已对齐」。

### 1.2 视觉判定容差

- 视口固定 **1424×805**（竞品少数截图为 1664×955，单独标注，不混算）。
- 布局盒：关键栏宽 / 高差 **≤ 2px**；间距 / 圆角 **≤ 1px**。
- 颜色：设计 token 必须完全一致；非 token 色差 **ΔE ≤ 2**。
- 字号 / 字重：字号 **≤ 1px**，字重完全一致。
- 内容差异（数据不同、语言不同、账号积分不同）必须逐项列出，不能把「内容不同」当「布局对齐」。
- 截图对照只用于判断布局与视觉，不用像素差百分比做唯一门槛（字体渲染、抗锯齿、截图压缩会造成假差异）。

### 1.3 交互判定

每个核心流程必须记录：

1. 起点（哪个页面、哪个入口）；
2. 完成同一结果所需点击 / 输入次数；
3. 默认值（模型、模式、时长、分辨率、预算）；
4. 闸门（未定稿、未匹配、未登录、积分不足、审核拒绝）；
5. 反馈（loading / empty / error / success / 长任务进度）；
6. 破坏性动作的确认或撤销；
7. 键盘可达性（Tab / Enter / Esc / 方向键）；
8. 窄屏（1180 / 900 / 768）是否仍能完成。

### 1.4 每批 DoD（Definition of Done）

- `typecheck` / `lint` / `test` / `build` 全绿；
- 变更前后同状态截图（1424×805）+ DOM 测量 JSON；
- 关键流程点击计数脚本与结果；
- 台账 `ui-parity-ledger.md` 对应路由状态更新；
- 不触发竞品任何写操作；
- 涉及契约 / 表结构 / 模型目录时，同 PR 更新 `docs/02-architecture/`。

### 2.5 本轮新发现的两条关键事实

1. **匹配后端存在，但不是竞品的「组合任务」。**
   - `asset-match.service.ts:154` 的 `matchResources` 只做「抽取资产名 → 命中项目资产 → 写集级快照 → 把已定稿资产绑到现有分镜」；
   - 竞品证据（`episode.md:261-300`，服务注释已引用）把 `match-resources` 定义为**资产匹配 + 自动拆分镜的组合任务**；
   - 所以「把按钮接上」只能得到「匹配资产」，不能自动补分镜。要宣称竞品等价，必须补自动拆分，或在台账明确标注偏离。

2. **项目级导出历史后端已经有了，前端是空的。**
   - `GET /projects/:id/exports` 已在 `script.controller.ts:1070` 实现，聚合 `exports`（分镜 zip）与 `timeline_exports`（成片 mp4），支持分页、状态、下载签名、`truncated`；
   - 前端 `projects/index.vue` 的 `已导出` tab 只有空态；`reelflow/list.vue` 的 `已剪辑` tab 只用 `timeline_duration_s > 0` 猜；
   - 这意味着 P0-5 主要是前端接线，不是新造后端。
