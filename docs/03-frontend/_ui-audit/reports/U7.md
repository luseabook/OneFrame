## 3. 与计划的差异

- 计划 §5 U7 写「对比度达标」。本轮**没有**引入对比度工具（如 axe / lighthouse），只做了「焦点环可见」与「颜色 token 一致性」的人工核对，因此这一项标 🟡 而不是 ✅。
- 计划写「窄屏 1180 / 900 / 768」。本轮取 1024 / 900 / 768（1180 在 U6/U4 的布局断言里已覆盖编辑器与工作台，不在本脚本重测）。

## 4. 未验证项 / 风险

1. **对比度未量化**：没有 axe-core 之类的自动化对比度检查，也没有 WCAG 比值表；建议后续单开一批（`@axe-core/playwright`）。
2. **窄屏只覆盖 4 个页面**：编辑台、项目工作台、3D 导演台、画布在 900/768 下的完成路径未逐条断言（编辑器有 U4 的 1424 断言，窄屏未测）。
3. **英文环境只验证了公开落地页**：登录后工作台在 `of_lang=en` 下的长文案未逐屏断言（U6 只覆盖了新建弹窗）。
4. **焦点顺序**只验证「能推进且有焦点环」，没有断言语义顺序（例如工作台里 Tab 是否按视觉顺序走）。
5. **硬编码中文白名单会随时间腐化**：新增法务页/新页面若大量中文，基线需要重新生成；建议在 CI 里跑 `--cjk`（不跑 `--cjk-update`）。
