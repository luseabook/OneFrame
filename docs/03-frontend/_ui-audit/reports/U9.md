## 0. 用户看到的两个真问题

1. **「剧本创作」点下去是「全部项目」+ 新建项目弹窗**：侧栏把 `sidebar.create` 指向 `/projects?create=1`，而竞品的「剧本创作」是一个独立页（顶部灵感输入 + 剧本广场 + 我的剧本）。
2. **侧栏条目与竞品对不上**：竞品主分组是 首页 · 剧本创作 · 创作 Agent · 全部项目 · 工具箱；我们把小说改编/无限画布/剪辑台/广告剧/视频转绘塞进了主分组，团队分组还多了剧本集市/知识库/创作者中心/活动（活动在竞品是底部项）。

另外用户截图里出现「自动测试软件正在控制 Chrome」——那是预览浏览器由 Playwright 拉起并保持 CDP 连接所致，已改为普通 Chrome 打开（同 profile，登录态保留）。

## 1. 分析为什么漏了（如实回答）

- 台账 93 条是按**竞品路由表**建的，判定的是「L0 入口 / L1 视觉 / L2 交互 / L3 数据」四层；
- **没有做「侧栏菜单 → 路由」这一层映射审计**：L0 只问"有没有入口"，没问"点下去是不是同一件事"；
- 台账第 37 行（`/script-manage`）本来就写着 `L0 ❌ 无对应入口`、竞品证据「抓图为空屏」——也就是说我们**知道**没有这个页面，却仍然在侧栏放了一个同名的入口指向别处。这是本次问题的直接来源。
- 结论：功能分/UI 台账都不覆盖"导航语义"，这是分析与验收口径的漏洞，已单独记缺陷。

## 4. 仍未对齐 / 未验证（不要当成已对齐）

1. **竞品剧本创作页只有用户给的 1 张截图**（本仓库此前是空屏），所以只有「首屏结构」这一层可比；生成中、我的剧本有数据、筛选结果、返回旧版等动态态仍是 `⏳`。
2. **卡片封面**：我方 `market_works.cover_uri` 目前多为空 → 用稳定渐变占位；竞品是成品海报图，这一项不是"布局对齐"能覆盖的内容差异。
3. **顶栏差异**：竞品该页顶栏是「创作手册 / 商务合作 / 语言 / 铃铛 / 帮助 / 会员 / 头像」，我们有同样的胶囊组，但排序与图标未逐项测量。
4. **hero 输入的真实行为**：现在是「打开新建项目弹窗并预填标题」，竞品是「直接进 AI 剧本生成会话」；这是产品语义差异，需要产品口径，未擅自改成假实现。
5. **侧栏"更多创作"是新增分组**：竞品没有这个分组（它没有这些功能）。这是"我们不删功能、但不打乱主分组"的折中，属有意偏离。
