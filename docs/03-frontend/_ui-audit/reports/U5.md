## 3. 实现要点（为什么这么做）

1. **不重写整页**：`assets.vue` 保留「资产 / 主体库 / 抽取与匹配」三视图与全部既有行为，只**新增**「资产工作台」视图并把标题 / 副标题收成 computed；`createFolder` 的调用点从 `prompt()` 换成 `openFolderModal()`，其余资产库逻辑一行未动。
2. **`AssetWorkflow.vue` 独立成组件**：资产页只负责挂载，工作台自己管项目 / 集 / 镜上下文、资产列表、两段式状态机，避免把 457 行的资产库页撑成 1500 行。
3. **两段式的闸门**：`generatable` 先逐条算「不可生成原因」（角色走定妆图链路 / 已有参考图 / 无提示词），所以「下一步」的计数是**真正会提交的条数**，不是勾选数；已有参考图的资产不会二次提交（不重复计费）。
4. **重试只重发失败项**：`genRows` 每行独立状态，`retryFailed()` 只取 `state === "failed"` 的 id，`submitGenerate` 用 `indexOf` 过滤，天然不会重发成功项。
5. **绑定幂等**：先 GET 当前绑定 → 合并去重 → **集合未变大就不发请求**，并给「未重复提交」提示。服务端 `PUT` 语义是整体替换（`replaceStoryboardAssets` 内部按 bigint 去重），两边都幂等。
6. **配额口径**：`loadModels()` 遍历 `/models?capability=video&visible=true`，取第一个带 `scene_modes.storyboard_reference_video.media_limits` 的模型；取不到就显示「模型目录未暴露 media_limits，配额未接」，**不回落静态数字**。
7. **导入是两条路**：可选上传参考图（`POST /assets/upload` 拿 `uri`，随创建一起写入 `ref_image_uri`），或只建一条带描述 / 提示词的资产；角色类型在下拉里被排除（后端 `kind=character` 会 400101）。

## 4. 未验证项与风险（如实登记）

1. **3 集 × 10 镜的 after 是公式推算**（§2.6 B），未逐镜实测；e2e 的 mock 只有 2 个分镜。
2. **before 值是代码审计值**，不是同状态实测：旧 UI 已被本批替换，无法再跑一遍对照。
3. **角色资产的批量生成没接**：后端 `POST /projects/:id/assets/:assetId/generate-image` 对 `kind=character` 直接 400101（角色走 `/characters/:cid/portrait`）。UI 上把角色排除在批量生成外并给出可读原因；「角色定妆图批量生成」不在本单元范围。
4. **配额的视频 / 音频「已用量」未接**：服务端没有按媒体类型的用量聚合字段，界面上明确写「未接」，只显示上限与图片 / 总媒体用量。
5. **「首次免费」改「免费」**（§0.1）：无「是否首次」服务端计数，宁可少承诺。若后续加了首次计数，把 `EXTRACT_UNMETERED` 换成接口字段即可。
6. **L1 只做到比例对照，未做像素差**：竞品证据是合成图（`2912×1007`，左面板 1444 宽，与 1424 视口存在约 1.4% 缩放不确定），绝对像素差不作为判据；台账 #58 的 L1 仍是 🟡，不是 ✅。
7. **窄屏 900 / 768 只写了 CSS 断点**（`.aw-two` 单列、网格降级为 180px），**未截图验证**。
8. **导入的图片不做前端压缩**（直接 base64，限制 8MB 并给可读错误），与资产页 `compress()`（canvas 压到 ≤1600px）不是同一条路径；大图失败路径未测。
9. **dev 噪声**：并行写手保存文件会触发 Vite 整页重载，e2e 里出现 16 条 `/_nuxt/builds/meta/dev.json 404` + app manifest 相关 console error。已在断言里显式排除并打印条数（`dev-noise console errors: 16`），其余 console error 仍算失败。
10. **`projects/[id].vue` 的角色空态 AI 提取大卡**仍是禁用态（Lead 划定由 u2u3 接），本单元未碰。
11. **导出 / 发布 / 改视频类接口没有在本单元被调用**，e2e 只验证了「没有漏出去」（`除生图外未触发其它付费接口`）。
