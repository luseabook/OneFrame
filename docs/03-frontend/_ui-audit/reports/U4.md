### 2.2 保存三态可见 + 自动保存 + 离开 flush（不退化）


```text

PASS  「全部」视图里未定稿仍标 0
```

**发现的既有缺陷（已修）**：`onPointerUp` 的插入位换算 `to > from ? to - 1 : to` 与 `indexAtX()` 的语义（「摘掉被拖片段之后的插入位」）不一致——把第 1 段拖到第 2 段右边会被算回原位，**向右拖永远不动**。改为直接使用 `to`，并把插入指示线按「过滤位 → 原始索引」换算（`dropBeforeIndex`），否则向右拖时那根 2px 线会画在自己身上。左移、拖入、裁剪三条路径实测未受影响。

截图：`u4-05-drag-reorder.png`、`u4-06-trim.png`、`u4-07-rail-drag.png`。

## 3. 未验证项与风险（如实登记）

1. **中区播放器画面尺寸（竞品 884×497）未做数值对齐**：mock 时间线的片段没有可播放媒体（`download-url` 返回空），`.rf-video` 的实测尺寸取决于真实视频宽高比；本批只对齐了容器（x314~1416 / 1102 宽、553 高）。要判「播放器画面尺寸一致」需要在有真实成片的任务上再测一次 → 保持 `⏳`。
2. **3D 导演台顶栏高度无竞品证据**：我方取 64（与全站顶栏一致），竞品 `ref-facts.md` 未记顶栏高度，不做「已对齐」结论。
3. **3D 有数据态（角色 / 机位）无竞品证据**（`ref-facts.md` §7.2 列表第 4 项）：本批只验证默认值与布局；角色摆位、机位增删的视觉只做了我方自测（`__director3d()` 快照：`cameras=[{cam-1,fov:50}]`），竞品侧保持 `⏳`。
4. **旧存档不迁移**：`sceneScale` 默认 100→300、`camTarget.y` 1→1.2 只影响**没有存档**的场景；已有 `localStorage` / 服务端快照仍按原值还原（有存档的用户不会突然看到 300 %）。这是有意的：不覆盖用户已保存的取景。若要统一，需要一次显式迁移批次。
5. **历史栈是页内状态**：不跨刷新、不跨集（换集时清空，防止把上一集片段插进这一集）。撤销后的状态仍会走常规自动保存落库，所以「撤销」不是只看界面。
6. **U1 的 e2e 脚本当前跑不通（不是 U4 引起）**：`_acceptance/ui-parity-u1.cjs` 第一步点「文生视频」时按钮是 `disabled`，卡在 `projects/[id].vue` 的 `modeEnabled()` 门槛上；该文件本轮由 U2/U3 改写（工作树未提交改动）。U1 落在编辑台的四条断言（已定稿闸门 / 删除撤销条 / 切片越界 / 弹窗 Esc + 遮罩 + Space 不劫持）已在本脚本 §2.3–2.4 逐条复测通过。
7. **`ours-facts.md:403`** 仍描述旧 DOM（`span.rf-dirty`）。该文档是 2026-10-31 的取证快照，本批不改写历史证据；U8 重扫时更新。
8. **台账未改**：`ui-parity-ledger.md` 的 #50 / #53 / #54 行不在 U4 写 scope 内，建议由 Lead / U8 按下面 §5 的口径更新，避免与其他并行写手冲突。
9. **本脚本对 dev server 重建窗口敏感（环境性，非产品缺陷）**：U2–U6 并行在同一台 dev server 上保存文件时，Nuxt 会重建模块图，落在那几秒里的导航会白屏，`.rf-clip` 等不到。脚本已加「导航最多重试 5 次 ×15s」；实测在别的 agent 密集保存的窗口内仍可能整轮失败（曾出现 17/18、43/44），同一时刻单独探测页面又是正常的。收口时请在**并行写手停手后**跑一次，本报告记录的是 58/58 全绿那两次（`u4-result.json` 为最后一次全绿结果）。
