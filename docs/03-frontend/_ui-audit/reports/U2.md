## 2. 实现要点（与计划条款逐条对应）

### 2.1 P0-3 匹配资产接通

- 入口：生成台「提示词」行右侧的 `匹配资产`，由 `disabled + 即将开放` 改为可点（`.match-btn`）。
  门禁只有两条：有选中集、没有其它 busy —— 不拿「有没有分镜」当前置条件（匹配本身会写集级快照）。
- 请求：`POST /projects/:id/episodes/:eid/match-resources`，**响应体不当结论**（真实实现只回「已受理」形状）。
- 结果：只认 `GET …/match-result` 的 `status`。轮询 8 次 × 900ms，判定终态 = `1/2/3`；
  超时（仍是 0）→ 提示「已受理，但结果还没落库；稍后点刷新结果」，**不把受理写成成功**。
- 展示：状态胶囊（未匹配 / 部分未定稿 / 已全部匹配 / 有缺失）+ 四段计数
  （共 / 已匹配 / 未定稿 / 缺失）+ 未匹配项逐条原因（前 6 条 + 「还有 N 项未列出」）+ 「刷新结果」。
- 失败：`matchError` 走页内 banner + 面板内红字，文案取服务端 message（不可读时才用兜底 key）。
- 文案区分：`projectDetail.ui.matchNotSplit` = 「匹配资产 ≠ 自动拆分镜：本操作只做资产匹配与绑定，
  不新增分镜；需要补分镜请用左侧「AI拆分镜」。」——面板常驻，不靠 title 隐藏。
- 匹配成功后重取 `episode` 与 `projectAssets`（服务端会把已定稿资产绑到分镜），镜头卡状态随之刷新。

窄屏（≤1180）改为贴边 8px + 视口高，避免 616 宽在小屏溢出。

内容：

- **三 tab**：角色 / 场景 / 道具（竞品只有三个；我方「其他」类资产不因此变成不可绑定，
  它跟道具同 tab、单独分组展示，不冒充道具）。tab 有自己的状态（`drawerTab`），
  不再复用资产视图的 `assetTab`——否则在抽屉里切 tab 会连带改掉资产视图。
- **搜索**：补上 `v-model="drawerSearch"`（台账 #11 的原缺陷），匹配名称 / 描述 / 提示词。
- **仅展示主体**：16px 复选，只留本集 `match-result` 里出现的主体；已勾选项始终保留（否则取消不掉）。
- **素材信息**：缩略图 + 名称 + 定稿状态（已定稿 / 未定稿 / 缺参考图）+ 已绑定镜数 + 「匹配」徽标。
- **可用性判定**：`ASSET_FINALIZED = 2`（与 `packages/shared` 的 `ProjectAssetStatus.FINALIZED` 同值），
  可当参考图还需 `ref_image_uri`。未定稿项**仍然列出**（用户要看见缺什么），但压暗、
  排在可用项之后，并带 `data-usable="0"`。
- **预选匹配结果（可取消）**：预选口径 = 本镜提示词/描述里出现过、且 `status=2` 的匹配项
  （与后端「按名字命中绑已定稿资产」同一口径，不把整集主体一股脑塞进这一镜）；
  点选即取消，另有「取消预选」只清匹配来源、保留原绑定与手选。
- **一键绑定**：`PUT …/storyboards/:sid/assets`（快照语义），成功后
  ① 抽屉关闭 ② `shot.character_ids` 用服务端回写的 `asset_ids` 覆盖 → 镜头卡缩略图、
  「已上传素材数 / 总素材」立即变化 ③ 落库（刷新后仍在）。
- **三态**：加载中（`assetsLoading`）/ 加载失败（`assetsError` + 重试，走同一 `loadProjectAssets`）/
  空态（按 tab 给「还没有{kind}资产」+「先去资产视图 AI 提取 / 生成 / 导入」引导）。
  无死按钮：取消 / ✕ / 遮罩点击 / 应用都可用（应用在 `drawerSaving || bindingBusy || !selectedShot` 时禁用）。

### 2.3 回归与韧性（自测中发现并修掉的一条真 bug）

U1 的 e2e 在本次改动后一度整页超时（`.mode-tab` 25s 不出现）。原因是：U1 的 mock 对未覆盖路径
统一返回 `{list,total,clips,items}`，而我在 `onMounted` 里新加的 `loadMatchResult()` 把它当
`match-result` 塞进 `matchResult`，模板里 `[...result.characters]` 展开 `undefined` 直接抛错，
把整个工作台 setup 打断。

修法（按"不信任响应形状"处理，不是改 mock）：

- `matchEntries` 对三类数组逐个 `Array.isArray` 兜底；
- `loadMatchResult` / `pollMatchResult` 只接受「三类数组齐全」的响应，否则丢弃并继续轮询。

修复后：U1 e2e 26 项里 25 项 PASS，唯一失败项是 U1 脚本自身的 console 过滤器没排除
dev 服务器 HMR 产物噪声（`[nuxt] Error fetching app manifest … dev.json 404`，编辑代码后的重建瞬间）。
U2/U3 脚本已把这条 dev-only 噪声排除在 "无未捕获 console error" 之外（不是放宽产品断言：
产品自身的 `console.error` 仍然会让该项失败）。

### 2.4 角色空态「AI 智能提取资产」接线（lead 追加项）

原状：角色为空时三卡里的白按钮是 `disabled` + 「即将开放」chip + `title=「智能提取资产即将开放」`。

现在（只改本页，**不动资产页 `assets.vue` 的同一入口**）：

- 按钮去掉 `disabled` / `soon-chip` / 编造的禁用 title，改为
  `@click="extractCharactersWithAi"`，运行中显示 `projectDetail.ui.extracting`（「提取中…」）。
- 请求：`POST /projects/:id/assets/extract`（`script.controller.ts:835`），body 按
  `packages/shared/schemas/project.ts:111` 契约：
  `{ episode_id?: string; include_characters: boolean }`。角色空态的这条 CTA **必须带
  `include_characters: true`**，否则角色 tab 抽完还是空的；`overwrite` 保持服务端默认 `false`
  （重跑只补新条目，不覆盖已编辑文本，同 kind+name 去重）。
- 结果：沿用既有 `aiExtractPartsCreated / Updated / Skipped` 三个 key 拼 `aiExtractDone`
  （「AI 提取完成：新增 N，更新 M，跳过重复 K；请校验并定稿后再用于分镜生成」），
  `truncated` 时追加既有 `aiExtractTruncated`。**没有新增任何计数 key**。
- 回填：`loadProjectAssets()` 之后**再 `loadProject()`**——角色草稿走 characters 接口，
  不重取项目就只在库里有、界面上看不到（这条是这次接线的关键坑）。
- 失败：`error` 走页面顶部 banner；同时在按钮下方就地给 `data-extract-error` 一行
  （服务端 message + 「重试」按钮，重试复用同一函数），按钮保持可点。
- 无集时回落 `scope='project'`（用项目 `source_text`），不出现「必须选集才能点」的死按钮。

### 2.5 typecheck 里 `resource_row_id` 那条红

台账/lead 提到的 `MatchEntryDto 无 resource_row_id` 一红，**在我这一版代码里已不存在**：
匹配结果列表的 `:key` 原本写 `entry.resource_row_id`，已改为只用既有字段
`entry.kind + '-' + entry.name + '-' + entry.status`（本批写报告前就改了，行号已漂移到 2426 附近）。

> 如实登记一个 DTO 缺口（未擅自改，`apps/web/types/api.ts` 不在我的写 scope）：
> 后端 `MatchEntry`（`asset-match.service.ts:105`）**确实返回 `resource_row_id`**（快照行 id），
> 且 `resource_id` 可为 `null`（缺失项），而 `MatchEntryDto` 把 `resource_id` 写成非空的 `string`
> 且缺 `resource_row_id`。要让类型与后端对齐，应在 `types/api.ts` 补
> `resource_row_id: string` 并把 `resource_id` 改成 `string | null`；这会影响所有消费方
> （含 U5 的资产组件），建议由 lead 指派单点修改，我这边已用 `Boolean(entry.resource_id)` 兜住运行期。

## 4. 未验证项与风险（如实登记）

1. **不自动拆分镜**：我方 `matchResources` 无拆分镜；竞品是组合任务（`ref-facts.md` §3.7 / `episode.md:261-300`）。
   UI 已写明差异，但「30 镜一集一次匹配后全部预绑」这条计划验收**只在服务端绑定层面成立**
   （`bindFinalizedToShots` 按名字命中），e2e 未对真实 LLM 抽取做端到端（会消耗真实模型额度）。
2. **「仅展示主体」竞品语义未取证**：本批是自定义口径（本集匹配结果内），竞品「生效效果」仍 `⏳`。
3. **竞品「有数据态」抽屉未取证**（`ref-facts.md` §3.6：「列表/勾选/主体标记均未取证」）：
   网格列数（我方 3 列）、卡片内距、缩略图比例均按我方 token 推导，**不能算 L1 通过**。
   只有面板外框（616×733/底色/描边/圆角）与「三 tab」有实测依据。
4. **遮罩浓度**：竞品 ref-facts 写 `#000c`，但同图采样显示页面区域几乎未被压暗（^(19,20,25) / (10,9,11)），
   两者矛盾。本批保留我方 `rgba(0,0,0,0.55)`，未按单一来源改值 —— 记 `待复核`。
5. **匹配结果面板的入口位置**与竞品不同：竞品是提示词上方一次性 toast（`06-match-asset.png`），
   我方是常驻面板（因为竞品`status=1/2/3` 的 UI 从未取证，只能保证「可读、可刷新、不谎报」）。
6. **未做竞品同状态像素 diff**：字体渲染与数据不同（我方 3 资产 vs 竞品 0 积分空态），
