## 2. 逐款明细

## 2.1 即梦 AI（字节跳动 / 剪映系）

**官网短剧入口**：<https://jimeng.jianying.com/tools/ai-short-drama>（JM-01，等级 B）

### 2.1.1 入口与首页形态

- 页面顶部导航只有五项：`AI 图片` / `AI 视频` / `核心功能` / `创作指南` / `未来影像计划`，右侧 `中文` / `登录` / `立即创作`。（JM-01 导航文字）
- 短剧页是一张**独立 SEO 专题落地页**，不是工作台。H1 为「AI短剧 让故事，一幕幕发生」，副标「从剧本与角色出发，用 AI 生成镜头，让故事走向成片。」
- 页内 7 处「开始创作 AI短剧」链接（Hero、提示词示例区之后、四类剧种卡各一、尾屏）**全部指向同一地址** `https://jimeng.jianying.com/ai-tool/home?need_login=true`。（计数依据：抓取文本中该链接出现 7 次）
  → **可判定结论**：即梦在产品路由上**没有** `/short-drama` 这类独立短剧工作台；"短剧"是内容专题，不是应用模块。（A/B 级，依据 CTA 目标一致性）
- 页脚把「即梦 AI 官网 / 创作工作台 / 未来影像计划 / 创作者故事」并列为四个链接，其中「创作工作台」同样指向 `/ai-tool/home`。

### 2.1.2 短剧生产链路与步数（官方口径 3 步）

页面用「从分镜到成片」明确给出三步（原文引用）：

| 步 | 原文标题 | 原文要点 |
|---|---|---|
| 1 | 定剧本，备好角色与分镜 | "用一句话写清故事冲突，再拆出开场、推进与转折。为每个镜头标注角色、地点、动作和景别，准备清晰的角色图与场景参考。" |
| 2 | 逐镜生成，检查动作与衔接 | "在即梦AI中用文字描述生成视频，或以参考图片开始图生视频。每个镜头聚焦一个主要动作，预览后检查人物外观、视线与运镜。" |
| 3 | 筛选素材，剪辑为完整短剧 | "将可用镜头交给后期剪辑，按剧情组织画面，再完善配音、音乐与字幕，完成一段能够独立讲清故事的作品。" |

页面同时用四段能力把链路切块（营销口径，不等于产品内四个模块）：「剧本分镜 / 角色设定 / 视频生成 / 剪辑成片」。

**关键闸门（页面原文，价值极高）**：
- FAQ「可以一次生成完整的多集短剧吗？」→「**这页介绍的是逐镜创作流程，不承诺一次生成整部或多集短剧。**先完成剧本与分镜，再生成、筛选和剪辑素材。」
  - 这是官方主动把"不做什么"写在公开页上，属于典型的**预期管理式文案**，对降低"买了发现不能一键成片"的售后成本非常有效。
- 步骤间没有"定稿/确认"类闸门描述；官方没有提到"生成前预扣费""资产齐备才可生成"之类机制。**未取证**：是否存在分镜确认态、重生成策略、批量投递。

### 2.1.3 角色一致性方案

FAQ「如何改善AI短剧的角色一致性？」原文：

> 「先建立统一的角色设定，固定面容、发型、服装与常用道具。参考图尽量清晰，跨镜头沿用核心描述，并逐一核对人物外观和细节。」

页面「角色与参考图」段补充：

> 「整理人物的面容、发型、服装与关键道具，再以清晰的角色图作为制作流程起点。为后续镜头沿用核心描述，并逐镜检查外观，让连续叙事有可核对的依据。」

**可判定结论**：即梦公开口径的一致性方案 = **角色设定文档 + 参考图 + 提示词复用 + 人工逐镜核对**；页面中**未出现**主体库、角色卡、`@` 引用等资产化机制（"未取证"而非"不存在"）。对照 ReelMate/OneFrame 的"主体库 + @ 引用"，这是**弱资产化、强提示词纪律**的另一种路线。

### 2.1.4 布局模式

- 被抓页面是营销落地页：Hero → 提示词示例区（武侠动作/雨夜喜剧/地铁悬念三个 tab）→ 四段能力（左右图文交替）→ 四类剧种卡（编号 01–04）→ 三步流程 → 制作指南四条要点 → 8 条 FAQ → 尾屏 CTA → 四列页脚。**属内容型布局，不是产品 UI**（等级 B 的直接含义）。
- 产品内布局 **未取证**：`/ai-tool/home` 需登录；页面反复出现的"创作工作台"无静态快照。

### 2.1.5 成本与额度展示

FAQ「制作AI短剧需要多少费用？」原文：

> 「费用取决于使用的工具、模型、生成次数与后期工作量。即梦AI当前可用额度和生成消耗**以登录后的页面为准**。」

→ **公开页不给任何数字**，把额度与消耗推迟到登录态。这是本次调研里"回避报价"最彻底的一例（连"积分"这个词都没在短剧页出现）。

### 2.1.6 值得抄的 UI 细节（1–2 条）

1. **把"不承诺"写成 FAQ 正文**（原文见 §2.1.2）。对我方的直接可用形态：生成页/剧本页放一条"逐镜生成，不承诺一次成集"的常驻说明，比藏在协议里有效。
2. **官方示例提示词自带一致性约束句**。页面示例提示词结尾是：「保持两位成年角色的服装、武器与方位一致，冷青灰电影光影，不添加文字或字幕。」
   → 抄法：提示词输入框旁的"示例/模板"直接给带一致性约束的句式，而不是空白 placeholder。

### 2.1.7 明显缺点（1 条）

- **短剧没有独立工作台路由**，四类剧种卡与所有 CTA 都落回通用 `/ai-tool/home`（JM-01：7 处「开始创作」链接目标全同）。
  🟡 推断影响：一部剧的"角色 / 分镜 / 已生成镜头 / 第几集"没有载体，用户只能靠提示词复用与自己的文件夹管理；这与 ReelMate 的"项目→剧集→镜头"结构是两个物种。

**可判定结论**（A 级）：

### 2.2.3 角色一致性方案：三条并列命名（这是可灵最值得研究的地方）

> ⚠️ 本节证据最弱：产品是**桌面客户端**，官网只有下载页；Hub 的实际界面**没有任何公开页面可核对**。以下"链路"全部来自发布会媒体报道（D 级），**不等于产品 UI 实测**。

### 2.5.1 入口与首页形态

JY-01（官网，B 级）可抓到的结构：

- 顶部导航：`电脑端`（→ capcut.cn 专业版）/ `移动端` / `创作课堂` / `即梦AI` / `图片设计`，右侧 `立即下载`。
- Hero：「**剪映AI** 创作无限可能」+ 副标「AI生成与专业剪辑，让创意轻松成片」。
- Hero 下方是三段 tab：`视频生成` / `营销成片` / `AI音乐`。
- 全站 CTA **统一为「立即下载」**（页面出现 4 处），并标注「推荐 macOS v11.5.1 或更高版本」。

**可判定结论**：剪映的官网**不提供 Web 版创作入口**（与即梦/Vidu/海螺的"打开即用"形成对照）；"Hub"作为新工作台只能通过安装桌面端获得。

### 2.5.2 生产链路与步数（媒体报道口径，D 级）

JY-02 原文要点（照录）：

> 「剪映专业版推出了一站式创作工作台"**剪映Hub**"。它由**无限画布**与**多轨道编辑器**两部分构成。创作者可以从**一句话、一个参考视频或一份文档**出发，在无限画布上梳理思路、形成脚本，并调用**即梦、小云雀**等AI创作平台生成图片、视频和音频素材，随后进入**多轨道编辑器**进行精细调整，从而减少在不同工具之间反复导入、导出的操作成本。」

> 「剪辑环节，剪映专业版还推出了智能创作Agent"**剪映助手**"。用户可以通过对话与其共同构思和剪辑视频，也可以让它承担**素材整理、口播删减、字幕纠错和视频包装**等重复工作。对于已经形成成熟工作流的创作者，"剪映助手"支持**自定义Skills**。」

→ 链路可归纳为 **3 段 + 1 条并行支线**：
1. 起点（三选一：一句话 / 参考视频 / 文档）
2. 无限画布：理顺思路 → **形成脚本**
3. 调外部生成能力（即梦、小云雀）产出 图/视频/音频 素材
4. 多轨道编辑器精调 → 成片
- 并行支线：与「剪映助手」对话，让它做整理/删减/纠错/包装（可自定义 Skills）。

**闸门**：报道未提任何"脚本确认/分镜确认/资产齐备"闸门 → **未取证**。

### 2.5.3 角色一致性方案

- **唯一相关线索**（**不是** JY-02 正文）：百度百科「剪映Hub」条目的搜索摘要称「连接图片与脚本后自动生成人物、道具、场景等资产，批量产出分镜提示词，选择 Seedance 等模型可生成多段视频并预览成片」。该条目本次抓取被百度安全验证拦截（403），**摘要级、未核对**，仅作线索登记。
- → 可判定的只有：Hub 的资产概念包含"人物/道具/场景"三类，且由"图片 + 脚本"连接后自动生成（D 级弱）。
- **一致性如何锁定（主体库/@引用/参考图）**：**未取证**。

### 2.5.4 布局模式

- **双编辑器**：无限画布（发散、脚本、素材编排）+ 多轨道编辑器（时间线精调）（D 级，JY-02 原文）。
- 这是本次调研中**唯一**同时具备"画布"与"时间线"的产品形态；其余四款最多只有参数面板或对话。

### 2.5.5 成本与额度展示

JY-02 原文：

> 「为支持AI生成与视频剪辑的双重需求，剪映同步上线全新订阅方式"**AI Ultra会员**"，将**AI创作积分**与**剪映SVIP专业剪辑权益**纳入同一订阅体系。」

→ **可判定结论**（D 级）：剪映把"生成侧积分"与"剪辑侧会员权益"**合并进一个订阅**，而不是分开卖。这对"既要生成额度、又要专业剪辑"的短剧团队是最省心的定价形态。

### 2.5.6 值得抄的 UI 细节（1–2 条）

1. **三种起点并列**（一句话 / 参考视频 / 文档）。→ 覆盖了"我只有想法"、"我有参考片"、"我有剧本/文档"三种真实开场，比单一"从剧本开始"友好。抄法：新建项目弹窗给三个入口卡，而不是只有一个空白剧本框。
2. **画布与时间线分工明确**：画布负责"想清楚"（脚本/素材编排），时间线负责"调精细"。→ 抄法：我方 `/reelflow/edit` 若是纯时间线，可考虑把"分镜/脚本"放画布、成片放时间线，避免一个界面承担两种心智。

### 2.5.7 明显缺点（1 条）

🟡 **两套编辑器 = 两套心智模型**（画布 + 多轨），且**必须安装桌面端**（官网全站 4 处 CTA 均为"立即下载"，JY-01）。对多人协作/远程审片不友好（协作能力**未取证**，此处仅指出"桌面端"这一可核对事实带来的结构限制）。

## 3. 横向趋势归纳（≤8 条，每条对应前文证据）

> 说明：本节是**归纳**（🟡），每条后面的括号是支撑它的具体证据，方便评审挑刺。

**T1｜"项目/剧集"不是行业默认形态，外部世界的主流是"能力入口 + 一次生成"。**
即梦（短剧页→通用工具页）、可灵（目录全是单点能力）、Vidu（按能力分家 + Agent）、海螺（首页即生成框）四款都没有"项目→剧集→镜头"的层级；只有剪映 Hub 用"画布草稿"承载了类似角色，且它是桌面端。（JM-01 / KL-01 / VD-01 / VD-03 / HL-01 / JY-02）
→ 对 OneFrame 的含义：**我们做"项目化短剧流水线"是差异化，不是跟风**；但也意味着**没有现成参照可抄**，交互细节必须自己验证。

**T2｜角色一致性已收敛为"三档强度"，且用命名而不是用参数来表达。**
弱=单张参考图（海螺 `参考 (0/1)`、可灵多图参考）；中=特征/长相参考（可灵【角色特征】/【人物长相】、Vidu 1–7 参考可提取角色/风格/构图/运镜）；强=持久化角色资产（可灵 数字角色 2.0、Vidu RefHub/资产一级导航）。（KL-01 / VD-02 / VD-03 / HL-01）
→ 命名即产品。我方 @ 引用如果只给"主体库"一个概念，用户无法判断"锁到什么程度"。

**T3｜`@` 引用已经成为跨产品的输入语法，是行业共性而非某家特色。**
Vidu 官方演示逐字为 `@牛仔 坐在吧台前` / `@酒吧` / `@女郎拿着一瓶红酒走向他`。（VD-02）
→ 我方 @ 主体引用的方向是对的；差异化点不在"有没有 @"，而在"@ 背后是**本项目资产**还是**本次上传的参考**"——前者可复用、可审计，后者随会话消失。

**T4｜容量约束要印在控件上，而不是靠报错告知。**
海螺 `参考 (0/1)`；Vidu 功能页写「最多 7 个参考」。（HL-01 / VD-02）
→ 可直接落地的微交互：上传位显示 `已选 2/7`、`@ 已引用 3 个主体`。

**T5｜公开页"不给价"是普遍做法，但"单位"必须公开。**
即梦原文「以登录后的页面为准」；可灵用"灵感值"；Vidu 定价页 JS 化（抓不到）；剪映把 AI 积分并入 AI Ultra 会员。（JM-01 / KL-03 / VD-05 / JY-02）
→ 抄法：价格页给**单位与规则**（= 灵感值/积分、按月发放、档位越高单价越低），不给"本次生成要花多少"的承诺；把"扣多少"留在生成前的确认里。

**T6｜"多环节流水线"在外部是稀缺能力，多数产品停在"镜头工厂"。**
可灵文档目录里没有任何剧本/分镜/时间线项（A 级）；Vidu 三步即出片；即梦明确"不承诺一次生成整部或多集"。（KL-01 / VD-02 / JM-01）
→ 反过来说：**ReelMate 那种"制片工坊四环节"在外部并非标配**，可能正是它的护城河之一；这也解释了为什么 ReelMate 值得做主要参照。

**T7｜Agent 化的 UI 形态是"对话列表 + Skills 安装"，不是"更多参数面板"。**
Vidu Agent 页 `<title>` 即「对话列表」，Skills 通过"帮我安装Skills <github 链接>"的对话 + `VIDU_TOKEN` 环境变量接入；剪映助手"支持自定义 Skills"。（VD-04 / JY-02）
→ 我方若要做 Agent，需要的不是新面板，而是**会话历史 + 技能装配 + 凭证**三件套。

**T8｜"防误购文档"正在变成产品界面的一部分。**
Vidu 给出「参考生视频 vs 图生视频」7 维选型表；即梦在 FAQ 里声明"不承诺一次生成整部或多集"；两者都在**公开页**完成"你该买哪个 / 你不要期待什么"的解释。（VD-02 / JM-01）
→ 抄法：模式选择器旁放对照表；成片页放"本产品不做什么"的常驻说明。
