## 四、本轮修复的真实缺陷（4 个）

### 1. `POST /projects/:id/duplicate` 500 —— BigInt 序列化
- **现象**：复制示例作品返回 500 `Do not know how to serialize a BigInt`
- **原因**：`duplicateProject` 返回 `id: newProjectId`（bigint），Fastify 无法序列化
- **修复**：`String(newProjectId)`
- **来源**：上一轮新增该端点时的疏漏

### 2. 余额不足导致整单失败 —— 违反 PRD「部分成功」语义
- **现象**：新用户赠送 80 积分，一条完整链路（定妆图 8 + 10 镜×8=80）必然超支，投递直接返回 `745701` 整单失败，用户什么都拿不到
- **原因**：`spent > balance` 时无条件抛 `INSUFFICIENT_BALANCE`
- **修复**：余额判断改为**逐镜截断**（`code=745701, reason=insufficient_balance`），只有「一镜都投不出去」才整单拒绝
- **效果**：实测从「0 镜成功」变为「9/10 镜成功」
- **回归测试**：新增 `truncates per shot when balance is insufficient`（api 测试 50 → 51）

### 3. 投递失败无明确原因 —— 用户不知道怎么办
- **现象**：角色未定稿时投递，界面只显示「已提交 0 个镜头」
- **修复**：
  - 全部失败时按 code 给出可行动文案（400105→「请先完成角色定稿」；745703→「请提高预算」；745701→「余额不足」）
  - 投递面板常驻提示「有 N 个角色未定稿」+「去完成角色定稿 →」跳转
  - 批次结果行新增「余额不足」标签

### 4. 投递后矩阵不刷新 —— 用户看不到状态
- **现象**：投递成功但分镜矩阵仍为空（只在 onMounted 加载一次）
- **修复**：`submitBatch` 完成后 `await loadMatrix()`

### 附：作品库封面 404
- **现象**：封面用 `results[0].uri`（对象键 `/u/...`）直接当 URL
- **修复**：改为「已转存图片资产 → 角色定妆图」优先，并通过 storage 签名成可访问 URL

### 附：静态资源 404 导致 Vue 未挂载
- **现象**：页面 HTML 引用的 chunk 在 `.output` 中不存在，Vue 应用未挂载（`__vue_app__` 为 false），交互全失效
- **原因**：web 服务进程持有旧构建，而 `.output` 已被新构建覆盖
- **修复**：清理 `.nuxt`/`.output` 后完整重建并重启服务
- **教训**：重建前端后必须重启服务进程，不能只替换产物目录
