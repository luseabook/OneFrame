# Web M1 端到端验证记录（2026-10-24）

> 目标：验证「登录 → 选模型/报价 → 生成 → 轮询 → 下载入口」在浏览器内闭环。
> 环境：本地 PostgreSQL 18 + Redis 8 + `apps/api`(3000) + `apps/worker`(mock) + `apps/web` 生产构建(3001)
> 证据：`web-e2e-create-2026-10-24-v2.png`（1280×720，任务完成态）

## 流程与结果

| 步骤 | 观测 |
|---|---|
| 打开 `/login`，输入手机号与验证码 | 登录成功；`POST /v1/auth/login` 200，Set-Cookie refresh_token（HttpOnly, Path=/v1/auth） |
| 硬刷新进入 `/create/text-to-video` | 中间件用 refresh cookie 换新 access token；`/models`、`/me` 均成功 |
| 选择模型（天幕2.0）+ 输入画面描述 | 画幅/分辨率/时长选项由模型目录渲染（16:9 / 720P / 5s） |
| 点击「生成视频」 | 自动 `POST /credits/quote`（8 积分）→ `POST /generations`（Idempotency-Key）→ 余额 72、冻结 8 |
| worker mock 执行 | `RUNNING → SUCCEEDED`，写入 results，结算 8；`/tasks` 轮询到已完成 |
| 页面状态 | 顶栏「积分 72」；预览「已完成 100%」；右侧历史「已完成 8 积分」；下载入口可用 |

数据库核对：

```
task.status=3, progress=100, credits_frozen=8, credits_settled=8
flows: gift +80 | freeze -8/+8 | settle 0/-8
account: balance=72, frozen=0
```

## 修复记录

- 首轮浏览器验证发现 `/me` 请求缺少 `Authorization`（Web 端 auth composable 未附 Bearer），导致余额 0、提交后报 `missing bearer token`；已在 `useAuth.call` 注入 access token，并复验通过。
- SSR/CSR 登录态渲染差异导致的 hydration warning：顶栏账号区改为 `<ClientOnly>`。

## 复现命令

```bash
# 1) 依赖服务（或使用 docker compose）
#    PostgreSQL 55432 / Redis 6380
# 2) 迁移 + seed
DATABASE_URL=postgres://app@127.0.0.1:55432/app pnpm --filter @app/api db:migrate
DATABASE_URL=postgres://app@127.0.0.1:55432/app pnpm --filter @app/api db:seed
# 3) 启动 api / worker / web
pnpm --filter @app/api dev            # :3000
pnpm --filter @app/worker dev         # mock executor
pnpm --filter @app/web build && node apps/web/.output/server/index.mjs   # :3001
```

> 说明：mock 结果 URI 为 `mock://results/*`，真实供应商接入（P1.4/P1.5）后替换为 OSS 预签名链接。
